# 文献插入、文内引用与文末著录

四项分别验收：来源存在、实际读取、支持当前命题、著录和标注正确。文末有条目不证明正文观点获得支持；编号没有报错也不证明引用完整。本模块的写作流程是质量指导，学院格式和标准要求另以明确来源约束。

## 在什么地方需要文献

| 内容 | 应怎样处理 |
|---|---|
| 定义、理论命题、他人方法或量表 | 找到真正提出或规定该内容的来源，说明本文采用什么及为何采用 |
| 外部事实、行业数据、政策与标准 | 使用对应机构、发布者或原始研究，保留日期、范围及适用版本 |
| 他人实证结果 | 同时核对研究对象、方法、条件和结果，不只复制摘要里的结论词 |
| 借用或改绘的图表、公式 | 在适当位置说明来源；实质修改说明改绘或改编，不把来源标成自己原创 |
| 本研究的数据、计算与观察 | 交代自身材料来源和方法，不能插一篇文献伪装成本研究结果的依据 |
| 作者的解释或建议 | 与已报告发现衔接，说明推理条件；借助文献的部分仍明确引用 |

不用固定“每段几篇”“中文英文各多少篇”“近五年必须占多少”的配额。来源的相关性、质量和实际支持优先；学院对数量或年限有明确要求时另行落实，不能为凑数插入未读材料。

## 如何把文献写进分析

先确定段落要说明的命题，再选择来源。综述可以比较几项研究的共同认识、分歧、证据和适用条件，最后说明与本文问题的关系；不要将作者姓名排列当作分析。

引用紧随其支持的内容，涉及多个不同主张时分开指明。某文献只支持定义，不能在合并长句后让它看似还支持经营收益或因果结论。文献在段落后出现，不自动表示覆盖本段全部论断。

直接引语核对原字、引号、删节和真实页码；改述也保留引用，不能只做同义替换。二手材料尽量追到原始来源，无法取得时按实际转引状态说明，不把二手引用登记成原文已读。

原创合成示例（编号仅演示）：

- 可以写“甲等[1]讨论了维护便利性与继续使用意愿的关系。本文据此关注维修流程的交接环节。”前一句须获该文支持，后一句是本研究选择。
- 不能将它改成“维护便利性决定复购率[1]”，除非原文确实支持这一变量关系和确定程度。

## 插入与维护步骤

1. 为来源保留稳定citekey、真实题录/DOI或来源链接、版本、实际读到的部分，以及支持命题的页码/段落定位。私人工作记录可加支持摘要，但不把版权全文复制进公共仓库。
2. 将命题与来源绑定后再插入引用。已有Zotero等文献管理器时保留原引文域和条目身份，不将域压平成普通文字，不擅自替换作者已有库或安装插件。
3. 按本项目的文末顺序编码制维护首次出现顺序；同一文献再次引用沿用身份与编号，并按需要保留引文页码。脚注等其他体系有相应例外，不能与本项目体系混用。
4. 插入、删除、移动段落后更新文内编号与文末表，并核对交叉引用。Word存在字段和已经刷新字段分开记录；目录或引用缓存不能仅因保存而视为更新。
5. 完成正文—文末双向核查，再做条目逐项著录与来源核查。重复DOI提示可能重复，最终是否合并由版本和实际内容判断，不自动删条目。

正文提及作者和年份本身不等于混用著者-出版年制；要检查实际标引方式和文末组织是否一致，不能机械删除有用的历史信息。

发现未在正文出现的文末条目时，先核对遗漏引用、误留条目或另列阅读型书目的可能，并按学院允许的实际用途处理，不自动删除。

## 当前MEM模板与GB/T 7714—2025

MEM以学院最新适用模板为准。本项目2026模板批注39规定数字方括号组合、叙述式引用与正文排齐、标题不放引用；批注74规定文末字体段距及2025版标准。普通引用是否统一上标需结合适用模板明确说明与最终版面核对，不能从旧论文批量推定。

已从[交大期刊中心发布入口](https://qk.sjtu.edu.cn/resource/file/11696)取得标准文本，核对所用条款及五页图像；读取范围和指纹见 [规范来源卡](normative-sources.json)。下表是查阅入口，不是标准全文或完整格式认证。

| 核对任务 | 条款与要点 |
|---|---|
| 责任者与题名 | 7.1—7.2：按信息源核对，西文姓名处理与学院要求一致；不替作者猜全名 |
| 页码、电子路径和标识符 | 7.6—7.9：按资源类型检查日期、引文页码及获取路径；URL内已有永久标识符可避免重复 |
| 期刊、书、学位论文 | 8.2、8.5、8.7：分类型核对来源、出版/授予信息、卷期和页码或文章号；不能统一套网页格式 |
| 会议、报告、标准 | 8.6、8.8、8.9：核对会议形态、报告编号或标准编号等对应字段；标准有独立著录规则 |
| 网页、数据、预印本 | 8.11、8.14—8.15与附录A：正确识别类型及相应日期、版本、路径；预印本不伪装已正式发表 |
| 文内编号与文末顺序 | 9.2：本项目采用顺序编码；多篇并引与重复引用按相应条款处理，不按作者字母排序 |

每类条目仍需核对标准规定的必备、有则必备和可选项，不能把可选字段说成一律必填。历史样本中的全大写西文姓、旧标准条目、缺页码或不完整网络著录不能覆盖2026模板和现行要求。标准元数据由[国家官方页面](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=C6CE52E55AC09B9C79A20AEA77CEDD14)核对；标准条款已读不等于任何现成CSL已通过符合性认证。

## 可选的只读检查工具

```bash
python3 scripts/check_citations.py manuscript.md
python3 scripts/check_citations.py manuscript.docx
```

工具检查数字引用候选的首次顺序、文内缺目标、文末未引用候选、重复编号、重复DOI和标题引用候选；不修改输入。输出退出码0表示所覆盖规则未发现问题，1表示有候选问题，2表示无法可靠解析。结果始终为partial。

方括号也可能是数学区间或其他标记。DOCX自动编号未展开、脚注尾注、修订、文本框及域缓存需要另行核对；扫描PDF中的上标应回看图像。工具不能核验文献真伪、全文支持、准确页码、全部引用覆盖或完整GB/T著录，不能把“无报错”写成“引用规范全部通过”。

工具报告采用的参考文献起止边界；纯文本后置标题缺少语义样式时标为候选并要求核对，避免把换行书目题名误当章节终点。
