# 格式适配与操作

## 选模板与规则

MEM论文一律以学院当前最新适用模板为准；本项目按用户明确要求采用现有学院2026版MEM模板。学院更新后重新提炼与核验，旧profile不得阻止更新。两套profile分别保存旧工程硕士样板历史对照和2026 MEM适配，旧版不作为当前MEM正式排版选项。旧样板内部也写“工程管理硕士”，文件名不等于本人应填学位名称。封面年份、元数据创建日期不是正式发布或适用届次证明。不得将旧文件当作交大全校最新规范。

profile记录来源指纹、读取范围与规则定位；读到文字不等于排版经过视觉认证。对实际稿件必须读取用户适用模板。正文、标题、摘要、表题等使用不同语义样式，不把“Normal”认定为全文正文。公式、引文上标、学科符号和特殊段落按实际情况处理。

2026模板中纸质装订方向、表格编号存在内部相反说明。电子副本可暂用左装订线5mm、表格按章编号，作为实现暂定项；在相关规则正式冻结前集中核定。英文摘要标题继承、行距类型等仅为实现默认的项目不得升格为学院硬要求。

学校通用指南保留学院自定格式的空间。[校级指南，2026-11-01访问](https://www.gs.sjtu.edu.cn/post/detail/Z3MzNDA0)。该网页仍建议GB/T 7714—2015；本项目2026 MEM配置采用GB/T 7714—2025，旧样板未据此证明采用新版。国家官方元数据列明2025版自2026-07-01实施，v1.1已从交大期刊中心取得标准文本并核对相关条款，见[规范来源卡](normative-sources.json)；这不认证任何CSL或脚本已全面符合新版。[官方标准元数据](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=C6CE52E55AC09B9C79A20AEA77CEDD14)。其他使用者按本人适用要求核定标准，不能简单按当前年份自动替换。

## DOCX局部工具

在skill目录运行；输入和输出可以使用绝对路径。工具使用Python 3.10+标准库，不调用Word、不上传文件。输出回执可能含文件信息，只存受控工作区。先用保真排版转换器将旧DOC副本转为DOCX，并核对分节、字体、字段和页码；转换不构成格式认证。实测 macOS textutil 转换这份旧DOC会丢失批注并产生Letter纸张，不能把该转换结果直接当排版母版。旧PDF含批注气泡，也不能从截图几何反推最终边距。

```bash
python3 scripts/docx_format.py inventory manuscript.docx
python3 scripts/docx_format.py inventory manuscript.docx --include-text
```

不加 `--include-text` 不输出正文。需要映射时在本地查看文本，建立以下JSON。段落序号是 `word/document.xml` 的 `w:body` 后代 `w:p` 的1起始序号，包含表格/文本框；节序号是该范围内的 `w:sectPr` 顺序，均不等于PDF页码。

```json
{
  "paragraphs": {"heading1": [1], "body": [2, 3]},
  "sections": [1]
}
```

示例数字只说明结构，不能直接用于真实稿。审核段落和节作用范围，排除封面、声明、前置特殊节与公式等特殊内容。稿件文字、表格或结构变化后重新盘点；不能沿用旧索引。可在map中加入 `source_sha256` 绑定输入；对输出运行audit时须更新该绑定到输出哈希，不能沿用原稿哈希。

```bash
python3 scripts/docx_format.py apply manuscript.docx \
  --profile profiles/mem-2026.json --map reviewed-map.json \
  --out manuscript-formatted.docx
python3 scripts/docx_format.py audit manuscript-formatted.docx \
  --profile profiles/mem-2026.json --map reviewed-map.json
```

apply仅将profile指定的字体与段落属性写入已映射段落，只调整映射节的页面参数。保留原有 `pStyle` 和 `styles.xml`，避免切断继承编号及按样式引用的目录/页眉；段落文本与其他ZIP成员保全。语义样式的建立与映射仍由完整模板工作流处理，局部工具不替换原样式。保留加粗、斜体、上下标等语义强调，不自动判断它们是否适用于每个字。复杂公式、文本框、修订及混合运行需特别核对，拒绝的输入先诊断，不能用删除修订或压平公式来强行通过。

输入文件不原位覆盖；输出已存在则更换文件名。audit只覆盖映射内已实现的属性，不能证明未映射区域、完整引用著录或视觉布局合规。

## 完整Word排版工作

局部脚本之外，使用当前环境可用的Word或文档工具完成：

1. 保留模板封面、声明/授权、前置页和节结构。真实个人字段从作者资料填写；签名不模拟。
2. 映射一至三级标题及纲要层级；章节另起页。建立真实TOC、SEQ、REF/PAGEREF等字段，不能把手打目录与页码称为自动字段。
3. 用分节控制封面不编号、前置罗马数字、正文从1连续阿拉伯编号；页眉引用当前章标题。核查断开链接与续编号，避免章后页码重置。
4. 图题在下、表题在上，按适用模板设置中英文和字体。图/题保持同页，续表重复表头和单位。需要三线表时明确设置上下线及表头线，不能套通用网格表设计。
5. 公式保持可编辑，编号和解释清楚。表格数据、缺失值、单位和有效数字按证据核对，不为排版凑数。
6. 正文引用与文末文献逐条双向核查，并按选定标准处理类型、作者、来源、年份、页码等。字号检查不能替代内容与著录核验。
7. 在同一排版环境更新全部字段并导出PDF，逐页查看。缺字/字体替代、孤行、标题落页底、断表、题注分离、公式截断、目录和页眉页码均需处理；修改后重导出检查受影响页及连带分页。

可用渲染器时生成逐页图像检查；没有时保留“未渲染/未视觉核验”。仅设置 `updateFields` 不代表字段已更新。LibreOffice和Word可能产生分页差异，最终使用实际交付环境核查。最终提交、盲审版本、声明表式和AI说明按真实学院要求办理，不由格式工具推定通过。
