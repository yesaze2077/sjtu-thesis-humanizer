# 分类审查入口

先识别论文各部分承担的任务，再选择对应模块。章节编号、章数和章节合并方式服从研究本身；不能按“第2章一定是理论、第3章一定是诊断”机械套用。

| 实际内容 | 本次需读的模块 | 分开记录的审查项 |
|---|---|---|
| 目录、中英文摘要 | [前置部分](sections/front-matter.md) | 目录；中文摘要；英文摘要；双语与正文一致性 |
| 研究背景、问题与已有研究 | [绪论与文献](sections/introduction-literature.md) | 绪论；综述；理论用途 |
| 数据、方法与业务现状 | [方法与诊断](sections/methods-diagnosis.md) | 方法；现状；原因及其证据 |
| 措施、实际执行与结果 | [设计与评价](sections/design-evaluation.md) | 方案；实施状态；评价；讨论与局限 |
| 全文结论与后续研究 | [结论与展望](sections/conclusion.md) | 小结；结论；局限；展望 |
| 引文及文末条目 | [文献插入与引用](citations.md) | 命题支持；插入位置；编号；著录；原文核验 |

全稿审查时逐项覆盖这些内容；某部分不存在或与其他章节合并，要记录实际位置及是否影响研究，不虚构缺少的分析。只审一章时加载相关模块及其与上下文的必要关系，无需一律读取全部模块。

| 部分 | 读者应该获得什么 | 重点检查 |
|---|---|---|
| 绪论 | 研究对象、具体问题、已有研究与本研究要回答的问题 | 从业务矛盾进入；不以宏大背景或“填补空白”替代问题 |
| 文献/理论 | 概念定义、研究分歧及选择依据 | 综合而非逐篇摘录；框架后续真正参与分析 |
| 方法 | 数据来源、观察单位、分析程序及其适用条件 | 说明为何能回答问题；资料不足不包装成正式编码或实验 |
| 现状/诊断 | 流程、异常、证据与可能原因 | 区分实际记录、作者回忆、推断；原因与表象有联系 |
| 方案/设计 | 措施针对什么问题、如何运行、为何这样选择 | 具体到操作与条件；实施与建议明确区分 |
| 结果/讨论 | 主要发现、解释、竞争解释及可应用范围 | 不逐格复述表；保留不利结果；证据与主张强度匹配 |
| 结论 | 回答研究问题，概括所得认识与不足 | 不新增结果；不把功能数量和交付数量当学术贡献 |
| 摘要 | 目的、方法、主要结果与结论的紧凑表达 | 稿件稳定后写，中英数值和确定程度一致，不添正文没有的结论 |

逐节核对“问题—分析—做法—评价”的对应关系，但不要在正文反复宣布这条链。每个小结应概括本节实际建立的认识；转入下一节时说明尚需解决的问题。保持章际术语、组别和指标定义一致。

高质量取决于研究本身及其论证。材料只能支撑过程描述时就做好过程分析；不能用语言修饰将其升级为成本节约、经济收益或因果证据。无法从已有材料回答的核心问题集中列出，避免逐句打断作者。

分类样本范围、原件指纹、可用全文读取与源文件完整性分别见 [来源卡](corpus-cards.json) 和 [分类审查矩阵](corpus-review.json)。跨论文重复出现只支持体裁参考；原文错误、过时规范和不适用于本研究的内容不能随样本一起复制。
